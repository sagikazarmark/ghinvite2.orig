# 404 Page Design

## Context

Issue #13 asks for a real 404 page instead of only returning a 404 status code. The open design question is whether the account console and the broader public surface should use separate 404 treatments.

`PRODUCT.md` defines ghinvite as a precise, calm product UI for GitHub account admins and recipients. `CONTEXT.md` now names the relevant surfaces: Public Surface, Recipient Flow, and Account Console.

The current code returns plain text for `WebError::NotFound`. Some 404s intentionally hide whether an account, invitation link, or request exists, so the new page must not reveal protected resource state.

## Goals

- Render a real HTML 404 page for browser-facing page navigation.
- Use public, recipient-flow, and validated account-console variants while sharing one reusable not-found view.
- Preserve the existing security policy that forbidden or unauthorized resources are surfaced as generic 404s.
- Keep non-page 404 responses minimal for action endpoints and assets.

## Non-Goals

- No resource-specific 404 explanations such as expired, revoked, unauthorized, or missing account.
- No new authorization behavior.
- No account lookup logic only to personalize public 404s.
- No ADR for this change, because the security behavior already exists and this issue changes presentation.

## Visual Direction

Physical scene: an account admin or recipient lands on a dead link while trying to complete an access task and needs a calm recovery path without wondering whether private resources were exposed.

Color strategy: restrained product palette using existing `ghinvite` and `ghinvite-dark` OKLCH theme tokens. Accent color is reserved for primary recovery actions and focus states.

The page should use system typography, existing button vocabulary, compact spacing, and current layout chrome. It should feel like part of the app, not a marketing error illustration.

## Page Variants

### Public 404

Use `HomeLayout` for unknown public page routes.

Content:

- Heading: `Page not found`.
- Body: `The link may be incorrect or no longer available.`
- Primary action: `Go home`, linking to `/`.

The public page may render with signed-out header controls. Signed-in dashboard recovery is handled by the existing home route, which redirects signed-in users with active installations into an account console.

### Recipient-Flow 404

Use `InvitationLayout` for `/i/...` failures, including malformed, unknown, expired, revoked, and exhausted invitation links.

Content matches the public 404 copy and `Go home` action. The focused invitation layout is appropriate because a broken invitation link is still part of the recipient flow.

### Account-Console 404

Use `DashboardLayout` only after account admin context has already been validated.

Content:

- Heading: `Page not found`.
- Body: `This page is not available in the current account.`
- Primary action: `Go to account overview`, linking to `/accounts/{login}`.
- Secondary action: `Go home`, linking to `/`.

The sidebar remains visible, but no sidebar item is marked active. The account login may be shown only because validation already proved the user can administer that account.

## Routing And Security

HTML 404 rendering should be route-aware instead of globally replacing all `WebError::NotFound` responses.

Rules:

- Unknown public `GET` and `HEAD` page routes render the public 404.
- `/i/{slug}` page failures render the recipient-flow 404.
- Unknown `/accounts/{login}/...` `GET` and `HEAD` routes attempt normal account-admin validation.
- If validation succeeds, render the account-console 404.
- If validation fails, return a generic plain 404 without account-console chrome.
- Existing dashboard handlers that fail because of malformed or missing resource IDs may render the dashboard 404 only when the admin context is already validated.
- `POST` action failures remain plain/generic 404 responses.
- Missing asset-style paths such as `/static/missing.css` remain plain 404 responses.

This keeps the UI helpful where the app has enough safe context and avoids confirming resource existence where it does not.

## Components

Add a not-found view module under `crates/web/src/views/`, exported through `views/mod.rs`.

The view should provide reusable not-found content with small variant inputs for:

- Public content and action.
- Recipient-flow content and action.
- Account-console content and actions.

The route layer should choose the layout because it owns the safe context: `HomeLayout`, `InvitationLayout`, or `DashboardLayout`.

Avoid new global CSS unless needed. If styling is needed, keep it minimal and use existing theme variables and component classes.

## Testing

Integration behavior should be covered where possible:

- Public unknown `GET` route returns `404`, includes `Page not found`, includes `The link may be incorrect or no longer available.`, and includes `Go home`.
- Missing or invalid invitation-link landing route returns `404` and renders the recipient-flow 404 copy.
- Unauthenticated dashboard route still returns generic 404 and does not include dashboard chrome.
- Authenticated and authorized admin visiting an unknown `/accounts/{login}/...` route gets `404`, dashboard chrome, `This page is not available in the current account.`, and `Go to account overview`.
- A `POST` action failure that returns 404 remains plain/generic and does not include the HTML 404 page.
- Missing static asset path returns plain 404.

Component rendering tests may cover the variants if full integration setup for an authenticated admin is too large, but behavior-level tests are preferred for routing and security boundaries.

## Acceptance Criteria

- Browser-facing public page misses render a real HTML 404 page.
- Recipient-flow invitation-link misses render a real HTML 404 page in the invitation layout.
- Validated account-console page misses render a real HTML 404 page in dashboard chrome with no active sidebar item.
- Authorization-hidden dashboard misses do not show dashboard chrome or the account login from the URL.
- Action endpoint and asset misses remain plain 404 responses.
- All 404 variants use generic copy that does not reveal whether an account, invitation link, or request exists.
